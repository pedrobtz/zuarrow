# zuarrow bug hunt, 2026-11-11

Commit `ff3dcba`. Hunters: 3 on Fable, run one after another, each blind
to the others and to the consolidated native review (`.agents/review.md`
on `review-consolidated`). Slices: the R layer; IPC decoding and limits;
emitting, lifecycle and ownership. Coordinator on Opus 5.5.

Built here, on macOS x86_64 with R 4.5.2 and Apple clang 17:

- the package;
- the package under ASan and UBSan, loaded with `DYLD_INSERT_LIBRARIES`;
- the standalone IPC reader under ASan and UBSan, through
  `tools/fuzz/harness.c` and a file-replay `main()`, since Apple clang has
  no libFuzzer.

The oracles were libarrow (the `arrow` package, with lz4 and zstd),
nanoarrow and DuckDB.

Unverified: the `_WIN32` path in `zar_read_path()`, big-endian hosts,
32-bit, and real data past 2^31 bytes or values.

Every reproduced trigger below was re-run by the coordinator on the
pinned install. Scripts are in `2026-11-11-bug-hunt-probes/`; see its
`README.md`.

## 1. Evaluate flatcc's `check_result` once, so a deep schema cannot stall the reader — #200, high, reproduced

- **Where:** [`src/vendor/nanoarrow/flatcc.c:2422`](../../src/vendor/nanoarrow/flatcc.c),
  `#define check_result(x) if (x) { return (x); }`. The macro is used in
  `verify_table_vector()`. `FLATCC_VERIFIER_MAX_LEVELS` is 100, at line
  2357. The `max_depth` check is at `src/zar_ipc_read.c:242`.
- **Trigger:**
  - `arrow_write()` of a list nested 48 deep, 5 KB, then `arrow_read()`.
    Depth 47 opens in 0.01 s. Depth 48 was killed at 30 s, in R, under
    ASan, and in the standalone reader.
  - Structs hang from 48 levels, maps from about 24, dictionaries at 62.
  - `arrow_limits(max_depth = 8)` does not help.
  - One flipped byte at depth 26 takes 1.2 s, about doubling per level.
  - libarrow reads these files, and refuses from depth 63.
- **Cause:** a failing child verification runs twice at every level, so
  the cost is 2^depth on the failure path. The failure itself comes from
  the verifier's budget: two levels per nested field, so it runs out at
  48, while zuarrow allows 64 and checks only after verification. Built
  with a budget of 200, depth 48 opens in 0.28 s.
- **Fix:** add a vendored patch that evaluates the result once, and offer
  it to flatcc and nanoarrow. Make the verifier budget cover `max_depth`.
- **Family:** 1: one limit in two units, and a side effect inside a
  condition.
- **Siblings checked:** list, struct, map and dictionary nesting all fail;
  a flipped byte at a shallow depth also fails.
- **Test the suite lacked:** read and write at depths 47, 48, 64 and 65
  under a time bound. Also run the fuzz target with `-timeout`: a slow
  input is not a crash, so the fuzzer never reported it.
- **Found by:** hunters 2 and 3. Hunter 3 found the macro.

## 2. Write a NULL or NA field name instead of crashing `arrow_write()` — #201, high, reproduced

- **Where:** `src/vendor/nanoarrow/nanoarrow_ipc.c:3716`, and the unset
  name at `src/zar_xptr.c:371`.
- **Trigger:** `names(df) <- NA_character_; arrow_write(df, NULL)` gives a
  segfault at address 0x0.
- **Cause:** the encoder passes a `NULL` `schema->name` to
  `Field_name_create_str()`.
- **Fix:** write `""`, as the reader presents it, or raise a
  `zuarrow_format_error`.
- **Family:** 4: the C Data Interface allows a NULL name.
- **Siblings checked:** a nested data-frame column fails too. A foreign
  handle with a NULL name reaches the same line by inspection; nanoarrow's
  R helpers cannot build one.
- **Test the suite lacked:** `NA` names at the top level, nested and in a
  list's item, through `arrow_write()` in both formats.

## 3. Write metadata by length so NUL bytes survive `arrow_write()` — #202, high, reproduced

- **Where:** `src/vendor/nanoarrow/nanoarrow_ipc.c:3688-3691`, the `_strn`
  builders.
- **Trigger:**
  `arrow_write(df, NULL, metadata = list(k = as.raw(c(0x61, 0, 0x62))))`
  reads back as `"a"`, in zuarrow, libarrow and nanoarrow alike.
- **Cause:** flatcc's `_strn` stops at a NUL. The decoder reads by length.
- **Fix:** add a vendored patch that builds the strings with
  `flatbuffers_string_create()`, which takes a length.
- **Family:** 3.
- **Siblings checked:** field metadata and extension metadata fail too.
  The C Data Interface keeps the bytes.
- **Test the suite lacked:** keys and values with NUL in schema, field and
  extension metadata, compared byte for byte in libarrow.
- **Found by:** hunters 1 and 3.

## 4. Refuse, not escape, non-ASCII native strings in a non-UTF-8 locale — #203, high, reproduced

- **Where:** `src/zar_xptr.c:47-60`, `zar_char_utf8()`.
- **Trigger:** under `LC_ALL=C`, `"\xc3\xa9"` is written as the 8 bytes
  `<c3><a9>`. libarrow reads that text.
- **Cause:** `Rf_translateCharUTF8()` escapes what it cannot translate, and
  the code assumes "a translation is valid by construction".
- **Fix:** convert with failure detection, and raise `zuarrow_type_error`.
- **Family:** 4.
- **Siblings checked:** factor levels, column names and metadata values
  fail too. Invalid bytes are escaped where a UTF-8 locale refuses them.
- **Test the suite lacked:** the same values under a C locale and a UTF-8
  locale.
- **Found by:** hunters 1 and 3.

## 5. Make a batch from `arrow_stream()` keep its registered column's memory alive — #204, high, reproduced

- **Where:** `src/zar_xptr.c:620` (`zar_c_stream_next`) and `:670`
  (`zar_c_array_borrow`).
- **Trigger:** with a `from` handler on one batch covering the whole
  column, take the batch, `rm(s); gc()`, then convert. ASan reports a
  heap-use-after-free in `zar_c_to_r`. Through libarrow, the Table read
  `19493 20 30` for `10 20 30`.
- **Cause:** ownership lives in R protected fields that the moved struct
  does not carry. `zar_c_from_r()` sets `keep`; `zar_c_stream_next()` does
  not.
- **Family:** 2.
- **Siblings checked:** multi-batch streams are copies and held. The
  deferred-strings child is #205.
- **Test the suite lacked:** assurance gap #189's sequence under ASan. The
  consolidated native review has this as R2.

## Cross-cutting

- **The vendored encoder lacks the decoder's guards.** Findings 1, 2 and 3
  are in vendored nanoarrow or flatcc, and two of them are in the encoder,
  which no fuzzer drives. The decoder reads metadata by length and treats
  a NULL name as `""`; the encoder does neither. Each upstream fix is a
  numbered patch in `tools/patches/`, offered to apache/arrow-nanoarrow
  and to dvidelabs/flatcc.
- **One batch and many must agree, and they don't.** Findings 13, 16 and
  17, assurance gap #198, and review R13 all change the result with the
  batch size. This is the differential the property test runs for
  built-in types, and it is missing for registered handlers and for zero
  rows.
- **Ownership on the R wrapper, not in the C struct.** Findings 5, 6 and 21,
  and #181. The C Data Interface lets a struct leave its wrapper, so
  whatever the struct depends on has to travel inside it (family 2).
- **The failure path is the untested path.** Finding 1's cost exists only
  when verification fails. Finding 8's stale state exists only after an
  error. The fuzz harness's oracle (a clean error, no crash) passes both.
  **Candidate rule for `correctness.md`:** bound the time and the state of
  every failure path. A fuzz target runs with a per-input time limit, and
  every object has a test that keeps using it after its first error.
  Family 1 covers the state after a failure. The cost of a failure that
  repeats its work is not yet in any family.

## Held: what was probed and stood

The full held lists are in each hunter's section of the probes README.
Briefly:

- **R values:** the value matrix (widths, NA of each type, 2^31 and 2^53,
  `-0`, `NaN`, Date, POSIXct with zones, lists, factors, zero length)
  round-trips through array, IPC and streams at batch 1 and 2.
- **Hostile session:** `OutDec`, `scipen`, `digits`, `warn = 2` and a
  non-UTC `TZ` change no bytes and no values.
- **libarrow both ways:** every listed type, in both formats and all three
  codecs, under `ValidateFull()` and `Equals(check_metadata = TRUE)`.
  102 random nested, sliced and chunked tables.
- **Byte layout:** over 108 outputs, every message is 8-aligned, there is
  one EOS marker, and the footer's blocks equal the real offsets.
- **Hostile bytes:** reader numbers mutated and straddled (lengths, null
  counts, buffer offsets, body lengths, footer, compression prefixes,
  codecs). Each is a classed error or matches libarrow. The whole
  arrow-testing corpus replays clean under ASan.
- **Limits:** every `arrow_limits()` field straddled on every source and
  framing. `ZAR_MAX_PREBUILT` at 255, 256 and 257.
- **Lifecycles under ASan:** reader stream lifetimes, chains, double
  release, handle sequences, top-level deferred strings after release.
- **Registry:** state after an error, and wrong output types and lengths.
- **Arguments:** `batch`, `level`, `columns`, `lossy` and `to`.
- **DuckDB:** reads streams and zstd files; zuarrow reads DuckDB's
  results.

## Not reached

- `ZAR_DIRECT_MAX` (16 validity bitmaps) and the conversion depth 64 at
  65. The first was not probed by any hunter; the second was blocked by
  finding 1.
- Sizes past 2^31: `(int32_t)` metadata lengths in `zar_ipc_write.c:139`,
  `large_utf8` past 2 GiB.
- Delta dictionaries nested in lists and structs; registered handlers on
  dictionary, run-end encoded and union columns; package-unload hooks.
- `arrow::RecordBatchReader$import_from_c()` directly, and ADBC (not
  installed); sockets, URLs and pipes as write targets.
- gctorture at step 20. Windows, big-endian, 32-bit and non-UTF-8
  multibyte locales other than C and ISO8859-1.

## Not reproduced, and by design

Nothing a hunter reported failed to reproduce. Not filed:

- **By design:**
  - POSIXct rounding to microseconds and a missing zone read back as UTC
    (D10);
  - `difftime` written as `duration[us]`, which reads back lossy (§6.2);
  - factor elements of a list taking the union of levels (§6.4);
  - `I(list(...))` refused (§6.2);
  - a data frame's `arrow_metadata` attribute not written, since
    `metadata =` sets it (§6.8);
  - `to` pieces combined with `c()` (§6.10, assurance #198);
  - changing dictionaries refused in the file format (§6.8).
- **Leniency with no wrong result:** a footer block's `metaDataLength` and
  `bodyLength` are ignored (libarrow checks them). zuarrow re-derives the
  sizes from the message.
- **Surprises for the maintainer, not filed:**
  - an explicit non-nullable field accepts `NA` and writes a null;
  - `arrow_schema("d:39,2")` is accepted;
  - names, dimnames and other attributes are dropped silently;
  - `arrow_equal()` compares doubles bitwise (`-0` against `0`);
  - error positions count from 0 in `arrow_equal()` and from 1 in
    conversion errors;
  - a file of two concatenated streams reads the first only;
  - unregistering mid-stream changes the conversion between batches with
    no signal;
  - a failed call consumes a stream, and a second `arrow_write(stream)`
    writes an empty file;
  - `dictionary = FALSE` is ignored for arrays and streams;
  - `.ARROWS` is the file format;
  - sliced run-end encoded arrays are refused on write.
